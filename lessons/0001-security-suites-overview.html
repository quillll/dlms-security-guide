Suite 0/1/2：先把三个旋钮分清

为什么学这个：你在实现/对接 DLMS 客户端与服务端。抓包里的第一道分岔口就是"这条报文用哪个套件、加了哪种保护"——分不清这三个旋钮，后面所有排错都会变成猜。
本课唯一要带走的一句话

安全套件（security suite）不是"安全等级"。套件决定"这条连接允许用哪些算法、密钥多长"；要不要加密、要不要认证，是另外两个旋钮（security policy 与 access rights）决定的。把这两件事混成一件，是绝大多数 DLMS 安全疑问的根源。

1三个旋钮：安全上下文

绿皮书 §9.2.2.3 把一次通信的"安全上下文"拆成三样东西。你在配置电表或在代码里设置参数时，动的永远只是这三样：

§9.2.2.3 Security context（本课只讲第 1 行；第 2、3 行是后续课程）
旋钮规范里的名字它回答的问题取值长什么样
①算法组合security suite这段连接能用哪些算法、密钥多长0 / 1 / 2
②保护要求security policy（+ access rights）报文必须被怎样保护，否则拒绝一个字节的位图，如 0x30；0 = 不要求保护
③密钥材料security material用哪把密钥、哪个证书、哪个计数器EK / AK / KEK / 证书 / IC…
别混进来的第四个概念

你在别处看到的 LLS / HLS（无安全 / 低级安全 / 高级安全的挑战应答）属于"认证机制"，规范在 §9.2.2.2 单独讨论。它是"你是谁"的问题，和这里的"报文怎么被保护"是两个维度：一条连接可以 HLS 认证成功，报文却完全不加密。绿皮书同时提醒：它给出的"三种认证安全等级"指的就是 no security / LLS / HLS。

表里出现的四个陌生词（AES-GCM、key wrap、ECDH、ECDSA）如果还是模糊的，先花两分钟看 密码学最小必要直觉——只看每节的第一句话就够。

从这张表读出的三条结论

  1. Suite 0 有加密，只是没有非对称算法。它的"认证加密"一栏写的就是 AES-GCM-128，照样能加密、能挂认证标签。它缺的是 ECDSA / ECDH / 哈希——所以它不能在协议内协商密钥、也不能做数字签名与证书认证。
  2. Suite 1 与 Suite 2 是同一个家族的两个强度档。128 位 / P-256 / SHA-256 对 256 位 / P-384 / SHA-384，连压缩算法都一样（V.44）。所以"选 1 还是 2"是强度与算力（嵌入式表计很在意）之间的权衡，不是功能有无之别。
  3. Suite 0 ≠ 不加保护。"不要求任何密码学保护"是 security policy 取值 0 的含义（Table 42 注），与套件编号无关。Suite 0 + 强制加密是完全合法的常见配置。
这条推论直接决定工程方案

需要"协议内协商/分发密钥、证书认证、数字签名"→ 必须 Suite 1 或 2。只能接受预置密钥 / 带外灌装 → Suite 0 就够，而且它是嵌入式设备最省算力的选择。这是为什么现实中 Suite 0（或 Suite 0 + 仅认证）出现频率极高——属于工程推论，不是规范陈述；规范本身没有规定任何套件是必选、可选或默认，也没有把任何套件标为废弃。

3在报文里认出套件：Security Control 字节

先知道它配在哪：设备上真正存放套件的是蓝皮书的 “Security setup” 接口类（class_id = 64）的属性 3 security_suite，格式为 enum：0 / 1 / 2（其余保留）。它由 Association 对象的 security_setup_reference 引用——所以套件是"每条应用关联"的属性，同一台表对不同客户端可以不同。细节与旧版本对象的坑见 套件速查 §6。

不用猜，也不用查配置——套件号就写在每个受保护报文的第一个字节里。这个字节叫 security control byte（SC），后面紧跟 4 字节调用计数器（IC），两者合起来叫 security header：SH = SC ‖ IC（§9.2.7.2.4.2）。

bit 7C 压缩
bit 6Key_Set
bit 5E 加密
bit 4A 认证
bit 3…0Suite Id

先自己试着读一个：0x30。

0x30 该怎么读？（想完再展开）

0x30 = 0b0011 0000：低 4 位 0000 → Suite 0；bit4 A = 1 → 认证；bit5 E = 1 → 加密；bit6 Key_Set = 0 → 单播密钥；bit7 = 0 → 无压缩。结论：Suite 0，认证 + 加密，单播密钥，E/GCM tag 96 bit，EK 128 bit。

下面这个解码器把位、套件表和 P/AAD 规则连在一起。把它点一遍：先用预设，再自己改位，直到你能预测结果再看答案。

两个真实的坑

①A 在 bit 4、E 在 bit 5——顺序与很多人记忆中的"A 在高位"相反。记反的代价是：你以为在加密，其实只做了认证（内容明文上网）。
②bit 6 是 Key_Set（0 单播 / 1 广播）。在 dedicated 或 general-ciphering 场景下该位不适用，规范要求置 0；某些实现会把它当"保留位"忽略，于是解出来的套件与保护都对、密钥却取错了。

4练一下：把知识变成能取用的记忆

不要回看上面。凭记忆作答，答完看解析——答错比答对更有价值。

Q1 · Suite 0 与 Suite 1 在算法能力上最关键的差别是？

  • 缺少椭圆曲线算法
  • 缺少分组加密算法
  • 缺少报文压缩算法
  • 缺少真随机数算法

解析：Suite 0 的认证加密一栏同样是 AES-GCM-128，所以它并不缺对称算法。真正缺失的是 ECDSA / ECDH / 哈希这整条非对称与摘要路线，这直接导致它无法在协议内协商密钥、也无法做证书认证。另三个干扰项都不成立：压缩是 Suite 1/2 的附加能力（V.44），随机的强随机数生成器则是 §9.2.3.5 对所有实现的通用要求，不在 Table 27 的套件差异里。来源：Table 27（§9.2.3.7）。

Q2 · SC 字节中 bit5（E）= 1、bit4（A）= 0，表示什么？

  • 只加密不认证
  • 只认证不加密
  • 加密并且认证
  • 不加密不认证

解析：E = 1 表示明文被加密；A = 0 表示不计算认证标签。对应 Table 46 的 “Encrypted only” 行：P = (C)I，而 AAD 为空——只有机密性，没有完整性保护。顺便注意这一档在报文结构里连 tag 字段都没有。

Q3 · security policy 的取值为 0 意味着什么？

  • 不要求任何保护
  • 只要求对称加密
  • 只要求数字签名
  • 只要求认证标签

解析：Table 42 的注写得很直接：policy version 0 与 1 下，“the value (0) means that no cryptographic protection is required”。这不等于 Suite 0——policy 是"要求多少保护"的旋钮，套件是"能用哪些算法"的旋钮，两者正交。

Q4 · 下列哪件事只有 Suite 1 / Suite 2 才能做到？

  • 协议内完成密钥协商
  • 报文内提供认证标签
  • 报文内提供机密保护
  • 报文内携带调用计数

解析：密钥协商需要 ECDH，而 Table 27 中 Suite 0 的 key agreement 一栏是 “–”，所以它只能靠带外预置或 KEK 包装来建立密钥。另三项与套件无关或各套件都有：认证标签与机密保护由 AES-GCM 提供（Suite 0 也有），4 字节调用计数器属于 security header（SH = SC ‖ IC），与套件编号无关。
顺带记住表里另一处只有 Suite 1/2 才有的能力：V.44 压缩（§9.2.3.6，ITU-T V.44:2000 的 Annex B.1 packet method）。

闭卷三问（写下答案再展开）

1 · 不看资料，说出三个套件各自的"认证加密 / 签名 / 协商 / 哈希"。

Suite 0：AES-GCM-128 / 无 / 无 / 无，密钥传输 AES-128 key wrap，无压缩。
Suite 1：AES-GCM-128 / ECDSA P-256 / ECDH P-256 / SHA-256，AES-128 key wrap，V.44。
Suite 2：AES-GCM-256 / ECDSA P-384 / ECDH P-384 / SHA-384，AES-256 key wrap，V.44。

2 · 三个套件里，认证标签长度分别是多少？

都是 96 bit（t = 96，§9.2.3.3.7.6）——套件升级并不改变 tag 长度。会变的是密钥长度：EK 与 KEK 在 Suite 0/1 是 128 bit，在 Suite 2 是 256 bit。

3 · 一条报文里 0x11 是 SC 字节，说明什么？

0b0001 0001：Suite 1；A = 1（认证），E = 0（不加密）；Key_Set = 0（单播）；无压缩。即 Suite 1 的仅认证（GMAC）：内容以明文随报文传输、附带 96 bit tag，完整性有保护、机密性没有。规范记法见 Table 46 的 “Authenticated only” 行。
对照记忆：0x21 只差 bit5——那是 Suite 1 的“仅加密”（A = 0，E = 1），连 tag 都不计算与校验。A 与 E 谁是哪一位，这两个值是最好的检查尺。
